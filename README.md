# Astra

Astra 是《未来战争》公司编程比赛的 C++11 参赛程序。当前仓库已完成协议、会话、动作裁决、HTTP 服务、回放验证，以及首版经济、导航、三火箭建造与升级、开拓者任务、弱模型任务求解、夜间返航和武器防守策略。

## 构建

在 WSL Ubuntu 中运行：

```bash
cd /mnt/e/develop/C++/Astra
bash scripts/build.sh debug
```

构建产物：

- `build/astra`：HTTP 服务和回放程序
- `build/astra_tests`：C++ 单元测试

可用构建模式为 `debug`、`release` 和 `sanitize`。

本地脚本会静态编译 `sdk/jsoncpp/` 中由与 SDK 同版本的上游 jsoncpp 1.9.3 源码生成的 amalgamation，不需要系统安装 jsoncpp。参赛程序源码只引用 `json/json.h`，不依赖 nlohmann/json 或 cpp-httplib。

## 比赛提交

生成包含 CMake、参赛源码与 SDK 同版本的上游 jsoncpp 1.9.3 源码的压缩包：

```bash
bash scripts/package_sdk.sh
```

产物为 `dist/Astra-CoreGeek.tar.gz`，可直接上传到只接收 tar.gz 的比赛平台。压缩包根目录是 `CoreGeek/`，与官方示例一致，只包含 CMake、参赛源码和带许可证的上游 jsoncpp 1.9.3 源码，不包含测试或临时文件。

压缩包不依赖相邻的 `ThirdParty` 目录或系统 jsoncpp。平台在解压后的队伍根目录创建 `build/` 时，CMake 会以 C++11 和严格标准检查静态编译全部源码，并将程序输出到队伍根目录的 `bin/CoreGeek`，供平台直接运行 `./bin/CoreGeek`。

## 启动

本地开发时运行：

```bash
bash run.sh 8080
```

服务监听 `0.0.0.0`，接受任意 POST 路径。非法 JSON 会得到 HTTP 200 和保守空响应，服务随后仍可继续处理请求。

比赛平台编译后直接以端口参数启动 `bin/CoreGeek`，不依赖本地 `run.sh`。

回放 JSONL 文件：

```bash
./build/astra --replay artifacts/match.jsonl
```

也可用 `--replay -` 从标准输入逐行读取。每行请求对应 stdout 的一行 JSON 响应，诊断写入 stderr。

```bash
bash scripts/test.sh debug
bash scripts/test.sh release
bash scripts/test.sh sanitize
```

测试覆盖 UTF-8 JSON、协议缺失字段、基地左上角坐标与 2×2 占地、换边镜像布防、共享资源和角色冲突、昼夜攻击边界、三类武器目标选择、三火箭建造与升级、任务 prompt/命令/复核/提交闭环、HTTP 分包和异常恢复、官方 SDK 提交包、经济路径选择、多人移动预留，以及 1300 回合连续回放。新增回归覆盖缺钱补塔时的经济回退、跨武器伤害分配、双格任务点交互和任务证据记忆；操炮站位测试逐回合推进角色位置与火箭冷却，检查三座炮能否实际获得操作者。

## 当前能力边界

当前决策会根据商店价格和往返路程选择矿区，执行移动、采集和整包出售；多人路径会避开已观测障碍、建筑占地、角色占位和本回合已预留目标格。补塔会先检查共享金币预算，无法支付时工人继续出售、采集或经济移动。开拓者会前往并领取可用任务，双格任务点按完整占地判断交互范围；角色会根据剩余白天路程提前返回分配的武器操作位置，没有可分配武器时向基地周边回防。缺少关键字段、未知容量、不可达目标或缺少基地观测时会保守地放弃对应动作。

基地 `pos` 按 2×2 建筑左上角解释，占地向 Y 轴负方向延伸。程序由基地自动推导 12 格武器建造环和外侧 20 格围墙建造环；首日优先用 75 金币建造三座火箭发射台。未提供刷怪点坐标时，以基地朝地图中心的一侧作为近端压力侧，另两座建在背向地图中心的远端；下半场换边后布局自动做 180° 镜像。三座火箭完成后，一个工人负责购券与升级，顺序为两座远端先到 2 级、再到 3 级，最后升级近端；另一工人采集 10 块石头，只在机器人直线来向一侧建造黄色区域的 10 格半圈墙。墙线和火箭布局在换边后一起镜像。三炮全部升满、半圈墙建齐后，按迎敌正面向两侧的顺序将围墙逐座升到 3 级，最后将基地升到 3 级；升级券会校验建筑类型、等级、存活状态和使用距离。

三炮、迎敌半圈墙与基地全部满级且敌方基地仍存活时，一个工人负责召唤令采购与使用，其余角色继续原有任务。保留 300 金币作为重建资金，用余额按实际商店价格选择大型/BOSS 组合，优先最大化新增总血量，其次攻击力，并在相同时减少可能送给对方的击杀分和花费；不购买小型、中型召唤令。例如余额扣除预留后为 1000/1100/2000 金币、尚有十个名额且时间充足时，按默认价格分别选择十张大型、九张大型加一张 BOSS、十张 BOSS。这是压力估算策略，尚未通过正式对战测得最优胜率。

召唤令优先使用背包已有库存，采购会扣除全队库存、已用名额，并受背包空间、往返路程和天黑前可用回合限制。每天全队最多使用 10 张：会话按已发出的指令预留名额，仅在紧接的下一回合明确失败时退回，重复请求不重复计数，新的一天或半场重置。夜间角色优先操炮，不再采购或使用召唤令；防御建筑被毁或未满级时恢复补建、升级。后期消费策略由 C++ 执行，不增加平台模型调用。

夜间存在已观测武器和邻接角色时，策略会优先消灭正在威胁我方基地的机器人，并继续攻击其他可得分机器人：火箭搜索 3×3 聚类溅射落点，电磁炮估算共线穿透，加特林保持目标在合法 90° 锥形内；最多三座武器与三个角色通过联合匹配分配，操作者不会同时移动。选敌时共享本回合已计划伤害，并先安排射程较短的武器，减少重复轰炸；预计被击杀的机器人仍按回合末结算规则参与弹道阻挡。基地威胁距离与导航共用向下展开的 2×2 占地。

自进化任务激活后，程序会向平台模型发送包含完整题面、离线限制和严格 JSON 输出协议的 prompt。模型可直接返回答案，也可请求一条沙盒命令；程序会把实际命令结果交给模型复核后再由开拓者提交。当前任务的命令、结果、已提交答案与错误反馈会以有限历史带入后续 prompt，任务切换或新半场开始时清空，重复请求不会重复追加记忆。Markdown JSON、纯文本答案和损坏结构都有明确兼容或修复路径，活动任务中的开拓者昼夜均驻守任务点。

每局比赛包含交换位置的上下两个半场；先比较半场胜负，双方各胜一场时再比较两半场表现分总和，最终胜、平、负分别获得 3、1、0 个排行榜积分。Astra 因此优先保证基地存活和整局胜率，同时用任务分、机器人击杀分与生存分争取半场优势。当前战斗规划仍不预测机器人下一步，近端压力方向也需要真实平台日志校准；1300 回合回放仅验证连续请求响应、会话和指令边界，不会推进完整游戏状态，不能作为守满十天或最终得分的证明。

正式平台日志显示编译器为 GCC 4.8.5，提交格式为 tar.gz。项目要求 CMake 3.10 或更高版本，使用 C++11，并随包静态编译与 SDK 同版本的上游 jsoncpp 1.9.3 源码。本地已用真正的 GCC 4.8.5 和配套旧版 libstdc++ 通过 88 项 C++ 测试、HTTP 与 1300 回合连续请求验证；这不等同于完整公司判题环境的实测。平台实际模型能力仍需通过比赛运行结果继续调优。
