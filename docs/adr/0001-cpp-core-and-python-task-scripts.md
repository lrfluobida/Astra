# 使用 C++ 决策内核和 Python 任务脚本

用户确认平台支持 C、C++、Go、Rust 和 Python。Astra 选择以 C++17 为实现目标的参赛主程序，将局势判断、资源分配、战斗搜索、动作检查与离线模拟放在同一套内核中；通过比赛提供的 executeCmd 接口发送 Python 脚本执行任务。具体编译器、标准支持、操作系统和提交方式仍待平台环境说明确认。

这一选择服务于一周内交付以及最大化 PVE 表现分的目标：线上与离线共用算法实现，任务脚本则适应规则明确提供的 Python 沙盒。Go 的服务开发便利、Rust 的内存安全和全 Python 的迭代速度都是真实优势；目前更看重 C++ 内核支持批量模拟和候选搜索的能力。这里不声称任何语言天然带来更高得分。

平台模型固定，按能力一般、可能输出错误或不可用设计。模型用于信息提取和未知任务探索；确定性逻辑独立运行。模型调用通过平台 prompt 字段完成，不训练模型，不依赖外部模型服务，也不在主程序中嵌入 Python 或另建常驻脚本服务。

代价是维护 C++ 和任务脚本两种代码，并需要验证编译、序列化和脚本输出边界。用少依赖的单进程实现、明确的数据契约及共享回放测试控制这一成本。如果平台实际工具链不能支持当前实现目标，再针对环境调整标准或构建方式。
